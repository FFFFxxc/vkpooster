# VK Reposter Pro: безопасное восстановление очисток, клипов, историй и отложки

Дата: 2026-08-08

## Контекст

Безопасная версия 4.0 убрала прежние механизмы, которые могли выглядеть для VK
как компрометация аккаунта: перенос cookies, неофициальную авторизацию Kate
Mobile/VFeed, скрытые параллельные окна и массовые вызовы через `execute`.
Вместе с ними исчезли нужные пользователю функции: очистка стены и альбомов,
загрузка клипов через вкладки VK, отложенные истории и наглядный менеджер
заданий.

Цель этого изменения — вернуть удобство старой версии, не возвращая эти
небезопасные способы работы с аккаунтом.

## Цели

1. Вернуть две явные операции очистки: записей сообщества и фотографий
   альбомов.
2. Вернуть настоящий интерфейс загрузки VK Clips через обычные вкладки VK.
3. Добавить отложенные истории для сообществ, которые могут публиковать их
   через официальный API.
4. Переделать экран отложки в полноценный визуальный менеджер с превью,
   статусами, ошибками и историей.
5. Сохранить границу безопасности: пользовательский токен не покидает
   расширение; сервер получает только зашифрованные токены сообществ для
   серверных задач.

## Не-цели

- Не возвращать cookies, `remixsid`, web-токены, импорт сессий или их
  подстановку в запросы.
- Не возвращать Kate Mobile, VFeed, vkhost или имитацию стороннего OAuth
  клиента.
- Не добавлять автоматические лайки, multi-account действия или обход капчи,
  проверок VK и ограничений API.
- Не запускать несколько скрытых вкладок или окон для публикации клипов.
- Не отправлять на Render/MongoDB пользовательский access token.
- Не удалять данные без явного предпросмотра и подтверждения пользователя.

## Доверительная граница и учётные данные

| Операция | Где выполняется | Учётные данные | Передаются на сервер |
| --- | --- | --- | --- |
| Обычный постинг и репосты | Расширение | Локальный пользовательский/токен сообщества | Нет |
| Очистка стены | Расширение | Локальный пользовательский токен | Нет |
| Очистка альбомов | Расширение | Локальный пользовательский токен | Нет |
| VK Clips | Обычная вкладка VK | Текущая сессия браузера VK | Нет |
| Отложенный комментарий | Render + MongoDB | Зашифрованный токен сообщества | Только токен сообщества |
| Отложенная история | Render + MongoDB/GridFS | Зашифрованный токен сообщества | Только токен сообщества и файл истории |

Токен сообщества хранится в MongoDB существующим AES-256-GCM vault-механизмом.
Ни API, ни интерфейс не возвращают его в незашифрованном виде. Пользовательский
токен продолжает находиться только в `chrome.storage.local`.

## 1. Очистка публикаций и альбомов

### Интерфейс

На странице сообщества снова доступны две кнопки:

- «Очистить стену»;
- «Очистить фотоальбомы».

Обе открывают отдельное модальное окно с быстрым выбором периода (неделя,
месяц, пользовательские даты), счётчиком выбранных объектов, предпросмотром
нескольких первых записей/фото, предупреждением о необратимости и кнопками
«Начать»/«Отмена».

Во время работы окно показывает количество выполненных действий, оставшееся
число, ошибки и кнопку «Остановить». Остановка не отменяет уже удалённые
объекты и не запускает новые.

### Реализация

- Предпросмотр получает только нужные записи через `wall.get` и фотографии
  через `photos.get`/`photos.getAlbums`.
- Удаление вызывает по одному `wall.delete` или `photos.delete` за раз.
- Между запросами применяется постоянная безопасная пауза, а не пакетный
  `execute`.
- Временные сетевые ошибки повторяются ограниченно с возрастающей паузой.
- Ошибки защиты, капчи, flood control, неверного токена и запрета доступа
  немедленно ставят очередь на паузу и отображают пользователю причину.
- Удаление вложенных фотографий у поста возможно только для фотографий,
  владельцем которых является выбранное сообщество; внешние вложения не
  затрагиваются.
- Очистка альбомов перечисляет альбомы и предлагает выбрать конкретные
  альбомы либо все доступные. Перед удалением отображается список и число
  файлов в каждом из них.

### Почему используется пользовательский токен

Официальные методы `wall.delete` и `photos.delete` принимают пользовательский
токен. Токен сообщества не является заменой для этих операций, поэтому он не
используется как скрытый fallback.

## 2. Настоящие VK Clips через вкладку VK

### Интерфейс загрузчика

Возвращается отдельная страница `clips.html` со следующими возможностями:

- выбор и поиск сообществ;
- выбор нескольких целевых сообществ;
- drag-and-drop нескольких видео;
- описание для всего набора и отдельное описание для файла;
- опциональная публикация клипа на стене;
- порядок файлов и очередь;
- лог выполнения и история завершённых загрузок.

Выбранные локальные файлы остаются в открытой странице загрузчика и не
переносятся на сервер. Если страницу закрыть, незавершённая очередь безопасно
останавливается, а не пытается продолжить без файлов.

### Последовательный tab worker

Для каждого задания расширение открывает одну обычную видимую вкладку VK:

1. создаётся активная вкладка загрузки клипа для одного сообщества;
2. content script передаёт файл во фрагментах и заполняет доступные поля;
3. он ожидает подтверждённый результат интерфейса VK;
4. при успехе вкладка закрывается и начинается следующее задание;
5. при капче, защите, изменении интерфейса или ошибке вкладка остаётся
   открытой, очередь получает состояние `paused`, а пользователь видит
   причину.

Запрещены скрытые окна, `focused: false`, параллельные загрузки, чтение или
перенос cookies. Используется только уже авторизованная пользовательская
сессия VK в обычной вкладке. При отсутствии локального пользовательского
токена результат определяется интерфейсом VK; при его наличии разрешена лишь
дополнительная локальная проверка результата через официальный API.

## 3. Отложенные истории

### Пользовательский сценарий

Из popup и менеджера отложки можно добавить фото или видео истории, выбрать
одно сообщество, назначить дату и время, добавить CTA и разрешённую VK-ссылку.
До публикации пользователь видит вертикальную карточку 9:16, дату, целевое
сообщество, состояние и доступные действия «изменить время», «отменить» и
«повторить».

### Серверная модель

Для запланированной истории создаётся серверная задача:

- метаданные и зашифрованный токен сообщества хранятся в документе MongoDB;
- исходный файл передаётся отдельным ограниченным raw-upload запросом (не JSON
  и не base64) и сохраняется в выделенный GridFS bucket;
- worker берёт по одной due-задаче с атомарной блокировкой;
- в срок он получает официальный upload URL (`stories.getPhotoUploadServer`
  или `stories.getVideoUploadServer`), передаёт файл и вызывает `stories.save`;
- после успешной публикации медиа удаляется из GridFS;
- при окончательной ошибке медиа сохраняется на короткий срок для повторной
  попытки, после чего удаляется фоновым cleanup-процессом.

Ограничение размера одного файла устанавливается в конфигурации сервера и
показывается в интерфейсе. Начальное безопасное значение — 25 МБ на историю,
чтобы не расходовать внезапно ограниченный MongoDB Atlas.

### Ограничения VK

- Для публикации истории сообщество должно удовлетворять требованиям VK:
  быть верифицированным либо иметь предусмотренный VK статус для публикации
  историй.
- Ссылка истории валидируется до отправки: допускаются только внутренние
  ссылки `https://vk.com/...`; CTA доступен только там, где его поддерживает
  API сообщества.
- Ошибки токена, прав или проверки VK являются окончательными и не
  перезапускаются автоматически. Сетевые сбои получают ограниченные повторы
  с backoff.

## 4. Визуальный менеджер очереди

`scheduled.html` становится менеджером с вкладками:

1. **Посты** — локальная очередь публикаций;
2. **Ожидания** — сохранённые исходные посты;
3. **Комментарии 24/7** — серверные отложенные комментарии;
4. **Истории** — серверные истории с вертикальными карточками;
5. **Не выпущенные** — паузы, отмены и ошибки;
6. **История** — успешно выполненные задания.

### Карточки постов

Карточка поста отображает аватар и имя целевого сообщества, время,
сохранённое превью вложения, текст, число групп, статус и действия. Превью
захватывается в момент добавления задания, чтобы открытие менеджера не
создавало дополнительную волну `wall.getById` запросов к VK.

### Карточки историй

История показана как вертикальная 9:16 карточка. Для фото отдаётся защищённое
превью с сервера по bearer-авторизации; для видео — первый доступный thumbnail
или нейтральная видео-обложка без скачивания всего файла в список. Список задач
не раскрывает исходный файл и не содержит токенов.

### Статусы и действия

Единая модель статусов: `queued`, `processing`, `scheduled`, `completed`,
`paused`, `failed`, `cancelled`. В зависимости от статуса пользователь может
удалить, отменить, повторить или увидеть точную безопасную причину ошибки.
Секреты, HTTP-заголовки и детали токенов в UI не отображаются.

## API и модели данных

### Новые серверные ресурсы

- `ScheduledStory` — метаданные задачи, статус, дата публикации, encrypted
  community token, GridFS file id, retry/lock-поля и безопасная ошибка;
- `story-media` GridFS bucket — содержимое временного фото или видео;
- защищённые маршруты создания, списка, отмены, повтора и получения превью
  истории;
- отдельный worker/сервис историй с теми же idempotency и stale-lock
  гарантиями, что и у комментариев.

Все новые API требуют имеющийся bearer `API_SECRET`, проверяют тип и размер
файла до записи, не принимают пользовательские VK-токены и не возвращают
зашифрованные поля.

### Расширение

- Очистка и Clip-очередь используют локальные модели и сообщения background
  service worker.
- Для Clip-очереди добавляется минимальное разрешение `tabs`; разрешения
  `cookies` и `scripting`, а также широкое `<all_urls>`, не добавляются.
- Content script для клипов ограничивается доменами VK (`vk.com` и `vk.ru`).
- Файлы клипов передаются только между открытой extension-страницей и одной
  вкладкой VK через долгоживущее message port соединение.

## Миграция

- Существующие локальные задания публикации сохраняются и получают превью,
  если оно уже доступно в сохранённых исходных данных; отсутствие превью не
  мешает публикации.
- Существующие комментарии на сервере не изменяются.
- Старые серверные аккаунты, cookies и пользовательские токены намеренно не
  мигрируются.
- Неудачные legacy-задания не запускаются повторно автоматически.

## Проверка и критерии приёмки

### Автоматические проверки

- unit-тесты валидации истории: тип, размер, дата, ссылка и CTA;
- тесты шифрования и отсутствия утечки токена в API-ответах;
- тесты GridFS lifecycle: создание, отмена, успешное удаление медиа,
  очистка просроченных файлов;
- тесты worker-а: атомарный claim, stale-lock, повторы и protective pause;
- тесты safety core: классификация защитных ошибок и невозможность
  агрессивного повтора;
- тесты manifest: отсутствие `cookies`, `<all_urls>` и неразрешённых host
  permissions;
- синтаксическая проверка всех новых extension-скриптов.

### Ручная проверка

1. Предпросмотр очистки показывает правильное число объектов, остановка
   прекращает запуск новых удалений.
2. Ни один пользовательский токен не появляется в запросах к Render.
3. Clip-очередь держит не более одной вкладки VK и останавливается при
   protective UI.
4. История появляется в MongoDB с зашифрованным токеном и GridFS file id,
   после успеха файл удаляется.
5. Экран отложки показывает карточки с превью и не делает массовых запросов
   к VK при каждом открытии.

## Риски и меры

| Риск | Мера |
| --- | --- |
| VK изменит DOM загрузчика Clips | Детектировать отсутствие ожидаемых элементов, оставить вкладку открытой и поставить очередь на паузу. |
| VK ограничит публикацию/удаление | Последовательное выполнение, пауза при protective errors, без обхода ограничений. |
| MongoDB Atlas ограничен по месту | Лимит файла, автоудаление медиа, видимый объём и безопасное удаление после результата. |
| Потеря browser service worker | Clip-файлы удерживаются открытой страницей, а очередь не продолжает работу молча. |
| Случайная массовая очистка | Обязательный preview, выбор альбомов, подтверждение и stop control. |

## Последовательность реализации

1. Тесты и безопасное ядро для локальных cleanup/Clip состояний.
2. Восстановление обеих cleanup-модалок и последовательного worker-а.
3. Визуальный менеджер отложки с локальными preview.
4. Серверные модели, upload и worker для stories.
5. UI создания и просмотра stories.
6. Страница Clips и последовательный tab worker.
7. Полная проверка, миграция, документация и deploy-инструкции.
