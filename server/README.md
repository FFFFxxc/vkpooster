# VK Reposter Safe Server

Сервер выполняет отложенные комментарии и Истории сообществ. Пользовательские
токены и аккаунты на него не загружаются. Токен целевого сообщества принимается
только при создании задания и хранится в MongoDB в виде AES-256-GCM шифротекста.
Медиа Истории временно хранится в отдельном GridFS bucket и удаляется после
успешной публикации или отмены.

## Что понадобится

- новый MongoDB Atlas cluster;
- новый Render Web Service;
- два разных случайных секрета;
- этот проект в GitHub/GitLab-репозитории, подключённом к Render.

## 1. MongoDB Atlas

1. Создайте отдельный проект и cluster.
2. В `Database Access` создайте отдельного пользователя только для базы
   `vk_reposter_safe`.
3. В `Network Access` разрешите исходящие диапазоны выбранного региона Render.
   Для первого запуска допустимо временно использовать `0.0.0.0/0`, но только с
   длинным уникальным паролем; затем сузьте список.
4. Скопируйте строку подключения драйвера Node.js, укажите в ней имя базы
   `vk_reposter_safe` и сохраните как `MONGODB_URI`.

Если пароль содержит `@`, `:`, `/`, `?` или `#`, закодируйте его как URI component.

## 2. Создание секретов

В PowerShell из папки проекта:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

Первая строка — `API_SECRET`. Не добавляйте её в Git. Blueprint сам создаёт
случайный `TOKEN_ENCRYPTION_KEY`; если вы создаёте Web Service вручную, используйте
для него вторую строку. Не меняйте `TOKEN_ENCRYPTION_KEY` после появления
заданий: без прежнего ключа уже сохранённые токены расшифровать невозможно.

## 3. Render

Проект содержит `render.yaml`, поэтому Render может создать сервис через
`New + -> Blueprint`.

Blueprint использует платный экземпляр `starter`. Это намеренно: бесплатный Render Web
Service засыпает после 15 минут без входящего трафика, поэтому не может надёжно
выполнить комментарий к отложенному посту. Для короткого теста можно вручную
выбрать `free`, но комментарии 24/7 тогда не гарантируются.

При создании Blueprint Render попросит задать:

- `MONGODB_URI`;
- `API_SECRET`;

`TOKEN_ENCRYPTION_KEY` Blueprint создаёт автоматически. Задавайте его вручную
только при создании Web Service без Blueprint.

Build command: `cd server && npm ci`

Start command: `cd server && npm start`

Health check: `/health`

После deploy откройте `https://ИМЯ-СЕРВИСА.onrender.com/health`. Нормальный ответ:

```json
{"status":"ok","version":"4.2.1","database":"connected"}
```

## 4. Расширение

1. Откройте `chrome://extensions`, включите режим разработчика.
2. Нажмите `Загрузить распакованное` и выберите корень этого проекта.
3. В панели расширения добавьте локальный пользовательский токен, если он нужен
   для чтения исходных постов/репостов.
4. Для каждой целевой группы добавьте её ID и токен сообщества.
5. В секции сервера вставьте Render URL и тот же `API_SECRET`.
6. Нажмите `Сохранить и проверить`.

## 5. Первый безопасный тест

1. Используйте отдельное тестовое сообщество.
2. Отправьте один текстовый пост без вложений.
3. Проверьте один пост с существующим публичным вложением.
4. Проверьте один отложенный пост с комментарием через 60 секунд.
5. Только после этого добавляйте остальные сообщества, не более 6–7 за одну
   очередь.
6. Для Историй сначала проверьте одно фото 9:16 без ссылки на тестовой группе.

Коллекции и GridFS bucket MongoDB создаются приложением автоматически. Для
Историй можно дополнительно задать `STORY_MAX_BYTES`; по умолчанию это 26214400
байт (25 МБ). После обновления этого репозитория Render нужно передеплоить, а
расширение — перезагрузить на `chrome://extensions`.

Если VK возвращает CAPTCHA, validation, flood-control или suspicious-activity
ошибку, расширение/сервер ставят задание на паузу. Не возобновляйте его до
завершения проверки в VK.

## Очистка данных на бесплатном MongoDB Atlas

На странице «Публикации и отложка» нажмите `Очистка данных`. Доступны три
независимых режима: удалить записи с ошибками, успешно завершённые записи или
всю завершённую историю. Активные, ожидающие и приостановленные задания эти
операции не затрагивают.

Очистка удаляет локальную историю постов и Клипов, завершённые документы
комментариев и Историй из MongoDB, а также оставшиеся файлы Историй из GridFS.
За один запрос обрабатывается до 100 Историй, чтобы не перегружать бесплатный
Render; если записей больше, интерфейс предложит нажать кнопку ещё раз.

## Локальная проверка сервера

```powershell
cd server
npm ci
npm test
npm run check
```

Запуск требует настоящих значений из `.env.example` в переменных окружения.
Файл `.env` намеренно не загружается автоматически: на Render используются
Environment Variables.
